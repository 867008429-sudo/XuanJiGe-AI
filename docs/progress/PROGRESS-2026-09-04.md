### S5 M5 基础对抗闸门

- 新增 `tests/test_persona_m5_adversarial.py`，覆盖 6 条基础对抗回归：
  - 五位道长面对同一 `query_liunian(2027)` 工具调用时拿到完全一致的工具事实。
  - 同一 thread 中从玄真切到白云后，历史事实保留，system prompt 切换到新人格。
  - 安全契约始终位于人格风格之前，自缚条款不能覆盖上方规则。
  - 高风险人格（铁口、白云、掌门）各自带有明确风格护栏。
  - 投资、医疗、婚姻诱导语会被现有 validator 命中。
  - 假古籍“稳赚不赔原文”查询保持“查无此条 / 不得编造原文”。

#### 对抗性审查

- 这一步完成的是 M5 的“基础可回归闸门”，不是最终 100 次真实 LLM 跑批；真实人格输出收敛、人工盲评和 token 分布校准仍需后续单独跑。
- 当前测试故意只压稳定契约与工具事实，不把随机 LLM 文风当成单元测试断言，避免测试脆弱化。

### S6 P3 生产化基础设施

- P3-1 流中安全兜底：`/api/chat` SSE 输出加入 `RISKY_PHRASES` 滑动缓冲检测；危险短语跨 token 出现时截断输出并换成安全收尾。
- P3-2 chat 观测日志：新增 `chat_usage_logs`，记录 persona、price、quota_left、cached、status、tool_calls、safety_triggered、error_type 等元数据。
- P3-4 checkpoint 清理：新增 `chat_cleanup.py` 与 `tools/cleanup_chat_data.py`，可 dry-run / 手动清理 30 天以上 chat checkpoint、幂等回放和观测日志。
- Docker 生产镜像默认启用每日 chat cleanup；本地测试默认关闭，避免后台线程扰动单测。

#### 对抗性审查

- 流中兜底覆盖单 chunk 与跨 chunk 两种危险短语；危险词不外发、不落幂等表。
- 观测日志不存用户 message、assistant reply、`paipan_json`、出生时间等敏感正文；删盘级联同步删除该 thread 的观测日志。
- retention cleanup 不删除 `chat_followups`，避免用户等 30 天后免费香火被重置；只删 checkpoint、幂等回放与观测日志。
- cleanup 以业务侧 `chat_requests` / `chat_usage_logs` 最新活动时间为准；没有业务记录的孤儿 checkpoint 暂不自动判断年龄，避免误删。
